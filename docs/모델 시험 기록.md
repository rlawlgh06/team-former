# 오픈라우터 무료 모델 시험 기록

쓸 모델 3개를 고르려고 2026-11-01 에 오픈라우터의 무료 모델을 실제로 불러 본 기록이다.
모두 앱과 같은 프롬프트(`assign_ai.build_prompt`)와 같은 파서·검사(`assign_ai.parse_plan`,
`rules.validate_assignment`)를 거쳤다.

문제는 부록 3(어려움) 14단계 직후 상태다 — 팀이 없는 학생 8명, 팀 4개,
팀1·팀2가 3명씩, 팀3이 2명, 팀4가 빈 팀. 솔버로 해가 존재함을 먼저 확인했다.

판정 기준

| 결과 | 뜻 |
| --- | --- |
| 통과 | 배정안이 공고 2.5절 4항의 검사 다섯 가지를 모두 통과 |
| 규칙위반 | 응답은 읽었으나 배정안이 규칙을 어겨 앱이 걸러 냄 |
| 빈응답 | HTTP 200 이지만 본문이 비어 있음 |
| 파싱실패 | JSON 을 찾을 수 없음 |
| 오류 | HTTP 오류 |

## 1차 시험 (오후 9시 무렵, 모델 7개)

```
nvidia/nemotron-3-ultra-550b-a55b:free               파싱실패  81.5s  'We need to assign 8 unassigned students to teams 1-4, respecting const'
google/gemma-4-31b-it:free                           오류      1.0s  HTTP 429: Provider returned error
thinkingmachines/inkling:free                        오류      0.4s  HTTP 403: only available on agentic plans
google/gemma-4-26b-a4b-it:free                       오류      0.7s  HTTP 429: Provider returned error
xingchen-agi/xing4.0-29b-a4b:free                    오류      1.9s  HTTP 429: Provider returned error
recursive/flint-v1.0:free                            오류      1.1s  HTTP 503: Provider returned error
dots-studio/dots-3-note-preview:free                 빈응답   43.9s
```

7개 모두 실패했다. nemotron 은 응답은 했지만 JSON 대신 추론을 글로 썼다.
이 결과를 보고 프롬프트에 "첫 글자는 `{` 이고 마지막 글자는 `}` 여야 한다" 를 넣고
`max_tokens` 를 8000 으로 늘렸으며, 글 속에 섞인 JSON 도 찾도록 파서를 고쳤다.

## 2차 시험 (프롬프트를 고친 뒤, 모델 8개)

```
nvidia/nemotron-3-ultra-550b-a55b:free               파싱실패 226.8s
google/gemma-4-31b-it:free                           오류      0.9s  HTTP 429
google/gemma-4-26b-a4b-it:free                       오류      1.1s  HTTP 429
xingchen-agi/xing4.0-29b-a4b:free                    오류      2.3s  HTTP 429
cohere/north-mini-code:free                          통과     39.3s
nvidia/nemotron-3.5-lightning:free                   빈응답   69.1s
thinkingmachines/inkling-small:free                  오류      0.8s  HTTP 403
nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free   빈응답   59.3s
```

`cohere/north-mini-code:free` 가 처음으로 통과했다.
nemotron 은 같은 프롬프트에 **226.8초**가 걸렸다. 앱의 120초 제한에 걸려 끊기는 경우다.

## 3차 시험 (오후 10시 20분 무렵, 모델 8개)

```
nvidia/nemotron-3-ultra-550b-a55b:free               통과     99.5s
google/gemma-4-31b-it:free                           오류      0.9s  HTTP 429
google/gemma-4-26b-a4b-it:free                       오류      0.9s  HTTP 429
xingchen-agi/xing4.0-29b-a4b:free                    오류      2.5s  HTTP 429
cohere/north-mini-code:free                          규칙위반  39.2s  팀3: 인원이 6명 (2~4명이어야 함)
nvidia/nemotron-3.5-lightning:free                   빈응답   72.7s
thinkingmachines/inkling-small:free                  오류      0.7s  HTTP 403
nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free   빈응답   89.5s
```

같은 모델이 시험마다 다른 결과를 냈다.

- `cohere/north-mini-code:free` — 2차에서는 통과, 3차에서는 **팀3에 6명을 넣어** 앱이 걸러 냄
- `nvidia/nemotron-3-ultra-550b-a55b:free` — 81.5초 파싱실패 → 226.8초 파싱실패 → 99.5초 통과

## 고른 모델과 이유

1. `cohere/north-mini-code:free`
2. `google/gemma-4-31b-it:free`
3. `xingchen-agi/xing4.0-29b-a4b:free`

1차는 유일하게 통과한 적이 있는 모델로 두었다. 2차와 3차는 제공자를 서로 다르게 골랐다.
구글 모델 두 개가 **같은 시각에 함께 429** 를 낸 것을 보고, 한 제공자에 몰아 두면
세 모델이 동시에 죽는다는 것을 알았기 때문이다.

`nvidia/nemotron-3-ultra-550b-a55b:free` 는 통과한 적이 있지만 99~227초로 느려
120초 제한에 걸리는 일이 잦으므로 쓰지 않았다.

## 배운 것

무료 모델은 믿을 수 없다. 세 번의 시험에서 호출 23번 가운데 통과는 3번이었다.
그래서 3차 모델까지 실패하면 앱이 스스로 배정하는 완전 탐색(`assign_solver.solve`)이
사실상 주된 배정 경로다. AI 배정은 그 위에 얹은 것이다.
