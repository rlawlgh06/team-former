# 팀 편성 웹 앱 구현 계획

> **에이전트 실행용:** 이 계획은 작업 단위로 구현한다. 단계는 체크박스(`- [ ]`)로 추적한다.

**목표:** 학생이 지원·투표로 팀을 만들고 마감 뒤 남은 학생을 AI 가 배정하되, 확정된 팀 구성이 언제나 규칙을 지키는 Streamlit 앱을 만든다.

**아키텍처:** 규칙 판정을 DB·화면에서 완전히 떼어 낸다. `rules.py`(순수 술어) → `engine.py`(메모리 `State` 위의 지원·투표·마감 상태 기계) → `db.py`(같은 판정을 트랜잭션 안에서 Postgres 에 반영) → `streamlit_app.py`(화면). 덕분에 부록 시나리오 15단계를 DB 없이 pytest 로 검증할 수 있고, 규칙이 한 군데에만 존재한다.

**기술:** Python 3.14, Streamlit, psycopg2-binary, bcrypt, requests, pytest

**스펙:** [`docs/PRD.md`](PRD.md)

## 전역 제약

- 테이블 이름은 모두 `tf_` 로 시작한다 (감점 13번)
- 화면 요소 `key` 는 PRD 6.1절 표와 **글자 하나까지** 같아야 한다 (감점 15번). `key` 에는 영문·숫자·밑줄만 쓴다
- `result` 안내는 `승인` / `대기` / `거절` / `막힘` 중 하나로 시작한다
- 비밀번호는 bcrypt 해시로만 저장한다 (감점 10번)
- `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD` 를 코드·로그·화면에 출력하지 않는다 (감점 7·8번)
- 무료 모델 자동 라우터 `openrouter/free` 를 쓰지 않는다 (감점 14번)
- 앱 코드에 연습용 시나리오의 학생 이름·단계 번호로 분기하는 코드를 넣지 않는다 (감점 19번). 시나리오 재현은 `tests/` 에만 둔다
- DB 연결은 프로세스당 한 번만 만든다
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자
- 필수 포함 역할 2개: 기획자, 웹 프로그래머 — **서로 다른 사람**이 맡아야 한다
- 팀 인원 2~4명

## 중점 검토 사항

스펙이 요구하지만 어느 작업의 테스트도 자연히 건드리지 않는, 실제로 깨지기 쉬운 입력들. 각 줄의 테스트를 해당 작업에 넣는다.

1. **BOM 이 붙은 CSV** — 나눠 주는 명단은 UTF-8 with BOM 이다. `utf-8` 로 읽으면 첫 열 이름이 `﻿student_no` 가 되어 전체가 깨진다 → 작업 8
2. **보조 역할이 빈 칸인 줄** — `2026002,라마바,웹 프로그래머,` 는 보조 역할 0개이지 `['']` 가 아니다 → 작업 8
3. **투표자 집합이 투표 도중 늘어남** — 내가 지원한 뒤 승인된 사람도 내 지원에 투표해야 하므로, "모두 찬성"의 분모는 저장된 값이 아니라 **판정 시점의 팀원 수**다 → 작업 3
4. **한 사람이 기획자와 웹 프로그래머를 둘 다 할 수 있는 경우** — 필수 역할 충족 수는 1 이지 2 가 아니다. 단순 카운트로 세면 7점짜리 기능이 통째로 틀린다 → 작업 2
5. **AI 가 JSON 앞뒤에 설명을 붙여 응답** — 무료 모델은 ` ```json ` 울타리나 서문을 자주 붙인다. 파싱 실패를 빈 응답과 똑같이 실패로 처리하고 다음 모델로 넘어가야 한다 → 작업 6
